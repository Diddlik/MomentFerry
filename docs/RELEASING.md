# Releasing MomentFerry

MomentFerry uses semantic versioning for tagged releases.

## Version format

Use Git tags in the form:

```text
vMAJOR.MINOR.PATCH
```

Examples:

```text
v0.6.0
v0.6.1
v1.0.0
```

Until v1.0, minor versions may contain breaking configuration/database changes when clearly documented in the changelog. From v1.0 onward, follow normal SemVer compatibility expectations.

## Container tags

The GitHub Actions container workflow publishes to:

```text
ghcr.io/diddlik/momentferry
```

A push to `main` publishes:

- `edge`;
- `sha-<commit>`.

A version tag such as `v0.6.0` publishes:

- `latest`;
- `sha-<commit>`;
- the SemVer tags generated by `docker/metadata-action`, meaning the full version and the matching major/minor tag.

`latest` therefore always points at the most recent release, never at a `main` build. This matters because the in-app updater waits for the running container to report the released version, and a `main` build is stamped `0.0.0-dev.<run>`. Deploy `edge` only when you intend to run unreleased code.

## Release checklist

1. Ensure `main` CI is green.
2. Review `CHANGELOG.md` and move relevant items from `Unreleased` to the new version section.
3. Back up a representative MomentFerry installation and test restore/recovery if database behavior changed.
4. Verify Dry Run, routing preview, Safe Move safety tests and Docker image build.
5. Confirm dependency/security alerts are addressed or documented.
6. Create an annotated Git tag from the intended `main` commit.
7. Push the tag.
8. Wait for the container workflow to publish the GHCR tags.
9. Deploy the versioned image to a test installation.
10. Verify `/health`, `/api/v1/status`, `/api/v1/storage`, routing preview and operation history.
11. Publish GitHub release notes from the matching changelog section.

Example:

```bash
git checkout main
git pull --ff-only
git tag -a v0.6.0 -m "MomentFerry v0.6.0"
git push origin v0.6.0
```

## Rollback

Prefer deploying versioned tags instead of `latest` in installations where deterministic rollback matters.

The example Compose file accepts a pinned image through `MOMENTFERRY_IMAGE`:

```powershell
$env:MOMENTFERRY_IMAGE = "ghcr.io/diddlik/momentferry:1.0.0"
docker compose pull momentferry
docker compose up -d --no-deps momentferry
docker compose ps momentferry
```

If an upgrade fails:

1. stop MomentFerry;
2. restore `/app/data` if the new version changed persistent state incompatibly;
3. pin the previous container version;
4. start the container;
5. keep Dry Run enabled until routing/recovery state is verified.

See [Backup and restore](BACKUP-RESTORE.md).
